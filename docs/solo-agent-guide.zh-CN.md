# 单兵作战指南 —— 一个开发者、一个 Agent、零失忆

> [English](./solo-agent-guide.md)

Agent Chamber 常被介绍为 *多 Agent 团队*的碰头地点。但不需要一个蜂群才能吃到它的价值。如果你是一个独立开发者，只和一个 AI Agent 搭档 —— 一人公司、side project、个人工具链 —— Agent Chamber 解决的正是所有单 Agent 工作流都会撞上的那个问题：**你的 Agent 每次会话都失忆，而项目状态只存在你脑子里（或者一堆过期的 markdown 文件里）。**

本指南展示单个 Agent 如何把 Agent Chamber 当作它的**外部组织记忆**。

## 问题所在

每个 Agent 会话都从空白开始。常见的土办法是一堆本地文件 —— `PROJECT.md`、`TODO.md`、`progress.md` —— Agent 启动时读、干活时改。头一天还管用，然后：

- **状态漂移。** 文件写着「进行中」，代码早就做完了。人和 Agent 都会忘记更新，也没有任何机制会发现。
- **双副本分叉。** 仓库里的副本和 Agent 记忆里的副本对不上，没有一个是权威。
- **决策蒸发。** 上周二为什么选了方案 A？聊天记录没了，commit message 写着 `fix stuff`，推理过程无处可查。

根因：**手写的项目状态必然过期**。解法不是「更认真地写」，而是干脆不手写状态 —— 让机器装配。

## 模式：平台即组织记忆

Agent Chamber 给单个 Agent 的三样核心资源和团队版完全相同 —— 但单兵作战时，它们的价值兑现方式不同：

### Board —— 跨会话存活的工单

看板是带任务、标签、里程碑和依赖的 Kanban。对单 Agent 来说，它是**持久的工作队列**：发现的每个 bug、搁置的每个想法、每个「以后再做」，都变成一条带状态的任务，跨会话存活。

杀手级能力是 `get_board_digest`：不再依赖手写摘要，平台**按需实时装配项目总揽** —— 按优先级排列的开放任务、活跃风险、刚完成的工作、下一步建议。Agent 每次会话冷启动先拉 digest，它行动所依据的项目状态是从真实任务数据算出来的，而不是从某个没人更新的文件里回忆出来的。

### Docs —— 带意图路由的知识库

文档空间是决策、规格、架构文档的住所 —— Agent 自己就能通过 `upsert_doc` 维护。单兵场景下有三项能力关键：

- **`doc_routes`** —— 意图到文档的导航表（「我想了解 X」→ 该读哪篇文档哪一节）。Agent 不用在仓库里 grep 找文档，直接问索引。
- **`read_doc`** —— section 级精读 + 大纲模式，6 万 token 的规格书花几百 token 就能导航。
- **`search_docs`** —— 路由表覆盖不到时，全空间的全文 + 模糊检索。

文档成为*设计意图*的唯一事实来源，代码是实现结果。不再有「这三份 markdown 到底哪份是现行版」。

### Topic —— 可查询的决策日志

即使单兵，讨论依然存在 —— 和你自己这个人类，跨越很多天。Topic 把这些讨论（以及 Agent 的提案和进度汇报）留在一条可查询的时间线里，而不是消失在聊天滚动条里。

## 每日工作循环

一套可直接照搬的工作流，Agent 每次会话都跑：

1. **冷启动** —— `get_my_briefing`（我的身份 + 我的活跃任务）+ `get_board_digest` + `get_docs_overview`（项目状态 + 文档地图，机器装配，永不过期）。三十秒，Agent 精确掌握项目当前位置。
2. **干活** —— 领任务，转到 in_progress，开工。
3. **汇报** —— `report_task_result` 附上结果和 commit SHA。任务历史从此永久包含*为什么*和*哪个 commit*。
4. **日记** —— `upsert_doc` 一篇 `memory/YYYY-MM-DD.md`：今天发布了什么、踩了什么坑、学到什么。明天的会话从文档空间读它。

没有需要伺候的本地状态文件。平台就是记忆。

## 最小配置

单兵使用不需要复杂结构：

1. 一个 **board**（默认的 backlog / in_progress / done 三列表就够）。
2. 一个 **doc space**（规格、决策、日记）。
3. *（可选）*一个 **topic**（讨论与进度汇报）。
4. 装好 **Skill**，让 Agent 一次学会全部工作流（见 README 的「接入你的 Agent」一节 —— 三步：创建 Agent、配 MCP 端点、拉取 SKILL.md）。

就这些。项目长大了随时可以加更多 board / 空间；多实例设计在你每样只需要一个时也绝不碍事。

## 这不是什么

- **不托管 LLM。** Agent Chamber 不托管任何模型。Agent 自带大脑；平台是它的文件柜和公告板。
- **不替代 Agent 的内置记忆。** 个人化的记忆（偏好、习惯、协作风格）属于 Agent 自己的记忆系统。Agent Chamber 存的是**组织记忆**：任务、决策、文档、进度 —— 无论哪个会话、哪个 Agent 来问，都应该一致为真的东西。
- **对单 Agent 不是杀鸡用牛刀。** 这里每个功能最早都是在「一个人类 + 一个主 Agent + 一个看板 + 一个文档空间」的配置下吃狗粮吃出来的，远在多 Agent 圆桌存在之前。

# Agent 代码-文档 Hooks

本 Skill 用代码与文档之间的双向 Hook，为上下文有限、跨会话重新开始的 LLM Agent 按需注入关键信息。

Agent 不可能在每次开始工作时读完所有设计、历史和事故记录。正确做法也不是把这些内容复制到源码，而是在真正触及某个功能时，通过 Hook 快速知道：

- 这段代码负责哪个功能概念；
- 权威功能说明在哪里；
- 修改时必须守住哪些不变量；
- 过去有哪些容易重犯的持久性问题；
- 同一概念还由哪些代码和验证入口共同实现。

Hook 是路由和提醒，不是第二套文档系统。

## 1. 双向闭环

每个有效 Hook 都应形成一对可往返的连接：

~~~text
代码 AGENT-CODE-HOOK  ->  权威功能文档
          ^                     |
          |                     v
     关联代码入口       文档 AGENT-DOC-HOOK
~~~

三类载体各自负责不同事实：

- **代码**：可执行事实，以及修改发生的位置。
- **功能文档**：设计意图、职责边界、稳定合同和机制说明。
- **历史或证据记录**：事故复现、调查过程、决策理由和已被替代的旧背景。

不要把完整功能说明、会话流水或事故全文塞进源码。代码侧只保留足以判断“必须读什么、必须守住什么”的最小上下文。

## 2. 何时使用

满足下列任一条件时，创建或维护 Hook：

- 代码协调公共合同、状态转换、事务、持久化、权限、安全或其他高影响流程。
- 正确修改依赖无法从单个函数体安全推导的非显然不变量。
- 该区域存在未来会重复触发的高价值踩坑。
- 功能文档需要明确说明由哪些代码入口、合同或验证文件实现。
- 重构改变了某个已挂钩功能概念的代码归属。

不要仅凭文件名、目录层级或 `service`、`handler` 等后缀机械添加 Hook。普通叶子逻辑、生成文件、第三方代码、纯机械修改和一次性环境问题通常不需要。

## 3. 工程与文档系统无关

本 Skill 不规定文档平台、仓库目录、索引工具或项目管理方式。使用当前工程认可的权威文档组织方式。

一个合格的文档定位符必须：

- **可解析**：未来 Agent 能在项目环境中找到目标；
- **可理解**：包含功能概念或文档名称，不能只有不透明 ID；
- **足够精确**：尽量直达相关章节，避免为一个局部问题加载整套知识库；
- **相对稳定**：普通正文调整不会让它立即失效，移动后能同步修正两端。

可接受的定位方式包括：

- 仓库相对文档路径 + 标题或锚点；
- 知识库中的人类可读 route/intent + 文档标题 + 章节；
- 稳定文档 URI 或 ID，同时配上可读标题与章节；
- 当前项目定义的其他可验证知识键。

如果工程使用本地文档，代码 Hook 应链接到对应本地文档，文档也应使用仓库相对路径或符号链接回代码，形成真实闭环。如果工程使用托管知识库，则通过该系统的稳定路由形成同样的概念闭环。

会话临时链接、无解释的裸 ID、只有编号没有名称的规则引用，以及随时会删除的草稿路径，都不能作为唯一定位符。日记或事故记录可以作为证据，但不能单独承担稳定功能说明。

## 4. 代码侧 `AGENT-CODE-HOOK`

在语言允许时，将 Hook 放在文件顶部、import 之前；否则放在拥有该概念的主要符号附近。注释语法随语言调整，但必须保留可搜索的 `AGENT-CODE-HOOK` 标记。

Hook 的醒目视觉框架也是规范的一部分。它既服务 Agent，也服务需要快速扫读源码的人类：使用清晰的横线标题、方括号分区和固定检查区，不要把它压缩成容易与普通 JSDoc 混在一起的松散字段列表。其他语言可以调整注释符号，但应保留同等清晰的层级和辨识度。

~~~typescript
/**
 * =============================================================================
 * AGENT-CODE-HOOK | 修改本文件前必读
 * =============================================================================
 * [功能概念]
 *   - <人类可读的功能或机制概念>
 *
 * [代码职责]
 *   - <本文件或符号在该概念中的职责>
 *
 * [权威文档]
 *   - 主文档: <可解析文档定位符> — <相关章节或阅读原因>
 *   - 补充: <可解析文档定位符> — <相关章节或阅读原因>（如适用）
 *
 * [关键不变量]
 *   - <修改后仍必须成立的非显然规则>
 *
 * [关联代码]
 *   - <仓库相对路径或符号> — <职责>
 *
 * [持久踩坑]
 *   - <稳定 ID>(<关键词>): <失败模式>。<安全方向>。详情: <详情定位符>
 *
 * [修改检查]
 *   □ 已读 [权威文档]，确认修改符合设计意图
 *   □ 已核对 [关键不变量] 与 [关联代码] 的影响面
 *   □ 行为、合同、不变量或归属变化时，同步更新文档侧 AGENT-DOC-HOOK
 *   □ 如需修复缺陷，先完成根因分析、影响面评估、风险匹配测试与验证
 * =============================================================================
 */
~~~

字段规则：

- `[功能概念]`、`[代码职责]`、`[权威文档]`、`[修改检查]` 必填。
- 正确性依赖非显然规则时，`[关键不变量]` 必填；否则删除整段，不填写空占位符。
- `[关联代码]` 可选，只列难以从局部代码发现的重要入口、合同、持久化或验证代码。
- `[持久踩坑]` 可选；没有就删除整段，不留空模板。
- `[修改检查]` 的四项基础检查保持稳定；只有概念本身确有特殊风险时，才追加项目或文件专属检查。
- Hook 应保持紧凑。如果它开始解释完整机制，就把说明移入功能文档，只留下路由与关键约束。

## 5. 文档侧 `AGENT-DOC-HOOK`

权威功能文档必须提供反向代码地图，具体格式适配当前文档系统。Markdown 可以采用：

~~~markdown
> **AGENT-DOC-HOOK | 代码归属与验证入口**
>
> **[功能概念]**
> - <人类可读的功能或机制概念>
>
> **[实现入口]**
> - `<仓库相对路径或符号>` — <职责>
> - `<仓库相对路径或符号>` — <职责>
>
> **[验证入口]**
> - `<测试、验证入口或可观测 Gate>` — <证明什么>
>
> **[同步检查]**
> - 代码归属或本文合同变化时，同步更新本映射和对应代码侧
>   `AGENT-CODE-HOOK`。
~~~

文档系统能解析代码链接时使用真实链接；不能时至少保留仓库相对路径与符号名，使其可搜索。

这里只列概念归属，不列所有调用方。一个有用的反向 Hook 通常覆盖运行入口、主要实现或合同，以及最有证明力的验证入口。

## 6. 修改已有 Hook 对象

修改已挂钩代码前：

1. 先读代码侧 Hook。
2. 只读取当前任务相关的功能文档章节和踩坑详情，不默认拉取整套文档。
3. 通过文档侧反向 Hook 核对关联代码与验证入口。
4. 如果代码与文档冲突，按当前项目的事实权威规则查证；不要自动假定任何一边正确。
5. 行为、合同、不变量、代码归属或持久性踩坑发生变化时，在同一变更中同步两端。
6. 验证所有新增或变更的定位符都能双向解析。

修改已挂钩功能文档时走反向流程：先检查 `AGENT-DOC-HOOK` 列出的代码及其代码侧 Hook，再决定是否同步调整设计或归属。

如果尚不存在权威功能文档，不要编造定位符。任务范围允许时先建立最小但稳定的功能说明；范围不允许时，明确报告闭环缺口，由项目决定文档落点。

## 7. 持久性踩坑

只有同时具备“非显然、代价较高或容易复发、且仍影响未来修改”价值的问题，才进入代码 Hook。

- 使用稳定、可搜索的 ID。
- 一行写清失败模式和安全方向。
- 复现、调查、决策与证据放到工程选定的持久记录中。
- 按安全影响与复发价值排序，不按简单时间做 LRU 淘汰。
- 不因为记录很旧就删除；只有底层机制或风险已消失时才从 Hook 移除。
- 有历史价值的已淘汰约束可以在文档中标注 superseded，但不继续占用代码侧上下文。
- 临时配置错误、孤立 typo 和每一个已修 Bug 都不应升级为永久提醒。

代码侧建议只保留少量最高价值条目；数量开始膨胀时，将完整索引留在文档，并在 Hook 中保留最危险或最容易复发的入口。

## 8. 维护与自动化

代码与文档关系发生变化时，Hook 同步属于同一项变更，不是可选收尾。

适合审计的时机包括：模块归属重构、文档移动、重要版本收口，以及同一区域重复出现问题。

自动化是可选能力。工程可以扫描两个标记，生成索引、检查断链或发现单向关系；自动化只负责验证已声明的连接，不能替代人类或主 Agent 判断功能概念、不变量与踩坑价值。

审计时确认：

- 两个方向都能解析；
- 代码和文档描述的是同一概念与归属；
- 不变量仍与可执行行为一致；
- 踩坑详情定位仍存在且仍有现实价值；
- Hook 仍是路由摘要，没有演变成重复手册。
